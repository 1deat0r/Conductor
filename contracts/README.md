# Protocol source of truth

`health-v1.schema.json` is the executable S0 health contract. The S1 command protocol adds versioned schemas for client submissions, server-canonical commands, typed actions, authority-scoped durable receipts, and command events. The schemas are consumed by both the TypeScript and Rust protocol packages before any endpoint or process-admission path is enabled.

Command and event schemas are closed to unknown fields and versions. Submission fields do not establish tenant, actor, device, or host authority. Runtime semantic validation binds operation-specific targets and aggregate revisions; unknown required events fail closed, while unknown informational events require snapshot recovery before sequence advancement.

The server-canonical command digest uses RFC 8785 JCS over the complete immutable `CommandV1` object with only `payload_digest` omitted, prefixed by `Conductor.CommandV1\0` and hashed with SHA-256. Create-command replay uses a distinct domain-separated submission fingerprint over the immutable submission plus authenticated tenant/actor/device context. Persist that fingerprint with the canonical command and coordinator receipt. For a repeated command ID, an equal fingerprint returns the original durable receipt and assigned IDs; a mismatch is rejected before allocating IDs or changing state. Duplicate JSON properties are rejected from raw input before normal JSON parsing; strings are not Unicode-normalized and all JSON numbers are safe integers.

Shared positive, negative, idempotency, deadline, duplicate-key, and JCS vectors live under `fixtures/commands/`. They specify contract behavior; they do not claim journal transaction durability, authentication, tool authorization, or process execution. Storage-level acknowledgement and recovery proofs remain in the S1 implementation gates.

`HostReceiptV1` currently defines typed receipt snapshots only. `updated_at_unix_ms` is descriptive, not an ordering value. No consumer may project, retry, reconcile, or recover from unordered receipt snapshots. The Critical board review of S1 host-receipt ordering ended in a terminal defer without adopting an ordering or transition design. Before a journal/API consumer is added, define and review generation-change reconciliation, atomic state/revision/outbox ordering, stale-writer fencing, and the SPEC R24 restore gate. See [the board outcome](../docs/decisions/board/2026-09-29-s1-host-receipt-ordering.md).

`command-json-inputs.v1.json` is the cross-language strict-input fixture consumed before schema validation or durable identity calculation. Both protocol packages reject duplicate decoded property names, invalid JSON/Unicode, non-finite or non-safe-integer numbers, and every raw number token that rounds to IEEE-754 negative zero. Strings are preserved without Unicode normalization. Callers supply a byte bound from trusted transport or operation policy; nesting is capped at 128. Parser errors share categories but not text.

These schemas and validators do not create an HTTP/IPC route, command admission path, or execution capability. S0 still exposes only `health-v1` and keeps execution unavailable. Runtime semantic authorization, storage durability, and recovery remain separate gates.
