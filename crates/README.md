# Execution substrate

`conductor-host doctor` and `conductor-supervisor doctor` print a truthful versioned scaffold envelope. They create no sockets, processes, repositories, databases, credentials or host enrollment. Unsupported invocations exit 2. The shared protocol crate validates cross-language fixtures.

The internal S1 storage foundation has two independent owners: `conductor-host` persists validated canonical `CommandV1` identity in a file-backed SQLite store, and `conductor-supervisor` persists local session intent/state in a separate file-backed SQLite store. Both use the shared `conductor-sqlite` durability configuration for a five-second busy timeout, WAL, synchronous FULL, and foreign keys; their schemas and ownership remain separate. Legacy host journal rows are quarantined and cannot be replayed as canonical commands. These stores are not wired to a CLI, API, renderer, or each other.

The host store exposes no production receipt snapshot, admission transition, or outbox consumer. The supervisor's Start intent is not process-launch authority; uncertain starts become `outcome_unknown` after restart and are never relaunched automatically. Query and Cancel remain internal storage operations. No process is spawned or owned, no command is admitted or executed, and health continues to report `execution_available=false`. Native process lifecycle, authenticated IPC, R07 receipt ordering, R24 recovery, and OS-specific PTY behavior remain unqualified. Do not infer S1 execution readiness from these storage modules.
