# rusqlite MSRV dependency probes

These are disposable, isolated proof probes for the S1 binding/MSRV choice. They are not Conductor product code and do not qualify Windows or macOS.

Each package pins one exact `rusqlite` version with `bundled` enabled. Its lockfile was generated by the candidate minimum Rust toolchain (`resolver = "3"`, edition 2024, package `rust-version` set to that minimum). The test uses a file-backed database, enables WAL and `synchronous=FULL`, commits one launch-intent row, closes and reopens the database, then reads the committed row.

| Option | Toolchain | Binding | Locked package count | Command and result |
|---|---:|---:|---:|---|
| Preserve | Rust 1.85.0 | rusqlite 0.39.0 | 31 | `cargo +1.85.0 test --locked --offline` — 1 passed |
| Latest | Rust 1.88.0 | rusqlite 0.40.2 | 32 | `cargo +1.88.0 test --locked --offline` — 1 passed |

The active workspace before adding rusqlite also passed `cargo +1.85.0 check --workspace --locked`. The probes establish that each exact binding/dependency snapshot and the basic bundled SQLite WAL/FULL operation compile and run on its candidate minimum on local x86_64 Linux. The real Conductor journal implementation still must pass its own tests at the selected minimum before the implementation commit, and the repository must add a CI job that keeps that minimum checked.
